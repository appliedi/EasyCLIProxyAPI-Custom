# Upstream v0.3.99 integration plan

**Goal:** Update the custom Windows build from upstream v0.3.76 to v0.3.99 as custom version 0.4.4.

**Architecture:** Preserve merge ancestry and integrate the official desktop release, including its pinned core 8.0.63. Retain custom subscription pages, persistent storage, Windows installer, and custom desktop update ownership.

**Spec:** `docs/upstream-merges.md` and the user's request to update our build.

## Tasks

- [x] Fetch the upstream release into a separate namespace and merge in an isolated checkout on `codex/custom-upstream-0.3.99`.
- [x] Resolve overlapping changes, review custom runtime/storage/updater integration, and set custom version 0.4.4.
- [x] Run TypeScript, frontend, Windows Rust, isolated-core, browser regression, and production build checks; fix integration regressions.
- [x] Record merge decisions and validation; commit the integrated source and prepare the build for review.

## Review focus

- Desktop updates must remain on appliedi/EasyCLIProxyAPI-Custom.
- New updater core-continuity behavior must coexist with storage and profile locks.
- Usage schema migrations must retain subscription fees and attribution.
- Storage snapshots must cover newly persisted files and SQLite state.
- Installer packaging must retain its resource allowlist and preserve user data.

## Decisions

- Use the desktop release's pinned core 8.0.63 instead of independently advancing to the latest core.
- Retain the fork's deterministic release pipeline, with no automatic core-version drift.
- Adopt upstream MCP layout and routing confirmation changes, preserving shared controls and localization.
- Preparation and local validation are authorized; publication and replacement of a running installation are separate steps.
